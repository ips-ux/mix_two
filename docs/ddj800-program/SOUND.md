# Sound Parity Plan (WS-F): Beat FX, Scratch and the Deck Sound

> **AI-generated:** Claude wrote this plan from strings in rekordbox 6.8.5
> (`rekordbox.exe`, `MidiMappings/*.csv`) and the Mix Two source tree. Effect
> names and parameter lists are **Observed**; how each effect sounds is
> **Unknown** until it is measured.

## Goal (owner, 2026-10-26)

Mix Two must **sound like Pioneer above all else**. Where Mixxx's sound
differs, it is replaced, not kept:
- Beat FX and the other rekordbox effects must match rekordbox's algorithms.
- Mixxx's turntable/scratch sound is to be scrapped in favour of rekordbox's.
- Algorithms from other Pioneer hardware may be added where we can obtain
  them (see the boundary below).
- New effects beyond Pioneer's ("Improve") come only after parity, and are
  marked as such.

## The boundary: match the sound, never copy the code

- **Allowed:** reverse engineering to learn *what* each effect is: its name,
  parameters, ranges, beat values, and which knob drives what. Measuring
  rekordbox as a black box: render known test signals through each effect at
  known settings and record the output.
- **Then:** write a behavioural spec per effect from those facts and
  measurements, and implement it from the spec alone (clean room).
- **Not allowed:** transcribing or translating Pioneer's decompiled DSP code.
  That would infringe Pioneer's copyright, and it is the ground rule of the
  whole program (ROADMAP §5).
- **Other Pioneer hardware:** effects that exist in rekordbox's software can be
  measured the same way (e.g. Smart CFX, Release FX, Merge FX, Pad FX, the CFX
  set). Effects that run in DJM mixer or controller **firmware** stay out of
  scope while the program does not touch firmware.

## Method

1. **Facts from rekordbox (static).** Per effect: parameter names and ranges,
   beat-value table, what the depth knob and parameter knobs control, on/off
   and release behaviour, BPM source (auto / tap).
2. **Oracle captures (dynamic).** rekordbox 5.8.7 in Performance mode with
   the DDJ-800, recorded with rekordbox's own REC (its rekordbox dj activation
   on this PC is permanent). rekordbox 5 has the same Beat FX table as
   rekordbox 6 (HELIX excepted) and an identical DDJ-800 mapping; a few runs
   are repeated in rekordbox 6 to confirm the algorithms match, see
   `tools/soundparity/README.md`. A test-signal pack generated by us
   (impulses, sine sweeps, pink noise, steady clicks and drum loops at fixed
   BPMs, a tone at a known key) is played through each effect over a grid of
   settings (beat values × depth × knob positions) and recorded with
   rekordbox's own REC to WAV. Controller input is replayed from recorded MIDI
   so that every run is identical.
3. **Behavioural spec** per effect: delay taps and feedback curve, filter
   types and cutoffs, LFO shapes and rates, wet/dry law, tails on release,
   tempo sync.
4. **Implementation** from the spec only, as Mix Two built-in effects with
   rekordbox's names, parameters and order. The DDJ-800 selector then loads
   them by identity instead of by position in the visible effects list.
5. **Acceptance:** the same test signals rendered through Mix Two, compared
   with the rekordbox captures (time-aligned difference, spectrogram distance,
   tail length), then a blind A/B listening test by the owner.

The deck sound follows the same loop: record jog and tempo MIDI once, replay
it into rekordbox and Mix Two with the same track, compare the recordings.

## Order of work (proposal)

1. Test-signal pack, capture procedure and comparison tool.
2. Capture and specs for the DDJ-800's 14 Beat FX; then implement them.
3. Scratch / jog sound and Master Tempo.
4. CFX set, Release FX, the remaining 20 Beat FX.
5. Single / multi Beat FX mode and rekordbox's FX panel (with the
   rekordbox-layout skin).
6. Then "Improve" effects beyond Pioneer.
