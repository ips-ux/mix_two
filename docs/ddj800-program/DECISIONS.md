## 4. Device export (Q3, Q4, Q13, Q14)

- Fundamental: library and playlist export to Pioneer gear in **both** the
  legacy format (PDB/ANLZ) and **Device Library Plus**. Device Library Plus
  and OneLibrary are one format (owner); we call it Device Library Plus.
  Target what **rekordbox 6.8.5 writes**; the owner exports with rb6 to all
  current hardware without problems.
- In scope: USB/SD export, **My Settings** on the stick, **Sync Manager** and
  device library maintenance (incl. legacy ↔ Device Library Plus conversion).
  PRO DJ LINK Link Export is deferred.
- An export row reaches **Checked** when the stick passes Mix Two's own
  reader and independent parsers (crate-digger, rekordcrate); a byte diff
  against a rekordbox-made stick is the debugging tool. It reaches
  **Deck-verified** when the owner sees rekordbox 6/7 show the stick exactly
  as it shows a stick rekordbox wrote itself, and **CDJ-verified** after the
  owner's tests on friends' decks (expected within days, not someday).

## 5. Analysis (Q14)

- Mixxx's analysers are the default and are converted to Pioneer formats on
  export. Analysis becomes a priority only if grids block Device Library Plus;
  then the target is rb6's analysis, not rb7's.
- **Existing rekordbox analysis takes precedence.** It is never overwritten or
  re-analysed automatically; only an explicit user action re-analyses.
  USB sticks are never written to when a DJ only plays from them.
- Unanalysed new tracks are **auto-analysed by default**. rekordbox's analysis
  settings are in Preferences as well as in the right-click dialog.

## 6. Library and files (Q15–Q21)

- **Sidebar:** no disclosure-triangle tree. Drill-in navigation (one level at
  a time, breadcrumb, BACK goes up, as on a CDJ-3000 browse screen), a jump
  box that finds any list at any depth, and pinned lists. Selecting a folder
  lists every track in it and below it (rb7 addition). The concept art is
  visual inspiration only; do not take structure from it.
- **Pane sizes:** fixed preset sizes switched with a button, as rekordbox
  does (no draggable divider in the Legacy skin). Initial heights match
  rekordbox 6.8.5 (to be measured).
- **Import in place:** a DJ can import a rekordbox library and leave every
  file where it is. **Consolidate** (gather files into the library folder)
  and **Back up** (mirror to a second drive or a Dropbox / Google Drive
  folder) are separate, optional offers. Consolidate + Back up are pre-selected
  and marked Recommended, but the DJ **can always proceed without a backup**.
  A quiet "No backup" status stays in the library; no repeated pop-ups.
- **Library location:** first run asks for a Local library (internal drive) or
  a Portable library (removable drive, clearly not the USB performance stick).
  The other kind is offered as the backup drive.
- **No watched folders.** Adding a track from outside the library folder asks
  to move it in (one question per batch, "do this for all tracks").
- **Consolidate safety (Q17):** copy, check by content hash, then send the
  original to the Recycle Bin / Trash; never remove from removable media;
  keep the file name, change only the folder; if the track is also in
  rekordbox, offer to update rekordbox's `master.db` (rekordbox closed,
  automatic backup first), else show a short Auto Relocate guide.
  "Rename files from tags" is a separate optional action.
- **Folder pattern** is a Preferences setting; default `Artist/<file>`;
  patterns from tags (album, year, genre…) possible.
- **Tags:** edits in Mix Two are written to the file at once, only for files
  in the managed library. A **Fix tags** work list holds tracks without artist
  or title: automatic save and resume, progress count, "Skip for now" (stays
  in `Various-Uncategorized/`) and "No artist needed" (SFX, samples →
  `Samples-SFX/`, never asked again). Tools: fill from file name, bulk edit,
  keyboard flow, AcoustID + MusicBrainz lookup with **confidence-based
  auto-apply**, a batch "accept all high-confidence" button, an undo log of
  tag changes, and a tunable confidence threshold.
- **Backup deletions (Q19):** deleting from a list asks "Delete from library?"
  and "Delete from backup?" (both unchecked). With backup on, every delete
  asks about the backup; there is no "always delete from backup" setting.
  "Delete from backup" asks "Are you sure?" (that confirmation can be turned
  off). Files deleted from the backup go to a hidden `_Removed` folder for
  30 days. **Restore from backup** lists what the backup has and the library
  does not, and copies it back.
- **Privacy:** a one-time notice before the first online lookup; every
  outgoing data flow is listed in a privacy policy (to be written).

## 7. UI (Q9, Q11, Q12)

- **Two faces, one engine.** Prepare/Export mode is a 1:1 rekordbox replica
  (with the sidebar improvement above). Performance mode moves towards
  hardware skeuomorphism.
- **Legacy Design** is the current target: rekordbox's performance layout
  with gentle hardware touches (centred mixer, SYNC / KEY SYNC styling).
- **Hardware Design** (the concept art direction) comes later with a real
  skin system. Plugging in a DDJ-800 shows the DDJ-800 skin; the DJ can
  switch skins. A **feature ownership** setting marks the connected gear's
  features against the skin's gear: Highlight owned, Desaturate unowned, Hide
  unowned, or No change (default). Unowned features are dimmed, never
  disabled. This needs a device → feature capability map.
- First round: **Legacy Design + DDJ-800 skin only**. The CDJ-3000 +
  DJM-900NXS2 skin waits for borrowed or donated gear. With no gear plugged
  in, Legacy Design (or the DJ's last choice) shows.
- **Text:** everything we write (tooltips, notifications, dialogs, prompts,
  errors, docs) is ASD-STE100. Pioneer and industry terms keep their own
  wording.

## 8. Platform (Q9, Q23)

- Windows now; **Linux as a first-class target** (the goal is that Linux runs
  better than Windows); the browser and self-hosted live streaming far later.
- Linux reference: **Linux Mint / Ubuntu 24.04 family**. The owner's laptop
  runs Mint XFCE on kernel 7.0; the DDJ-800 audio works there through the
  kernel's own `snd-usb-audio` quirk (kernel 6.4+), so no Pioneer driver.
- Packaging: `.deb` first, AppImage for other distros, **no Flatpak** (its
  sandbox blocks USB/HID and real-time audio). The `.deb` installs the udev
  rule and real-time audio permissions.
- No Windows-only code without a Linux path. The own-audio-driver work is now
  Windows-only (Linux has a driver).
